## Phase 92 goal

Create a reusable VisiForm splitter widget and use it between the Designer Canvas and Property Inspector.

VisiForm should increasingly use its own reusable widget and layout infrastructure to construct the VisiForm editor.

Follow a reusable-widget-first architecture:

* Prefer existing VisiForm widgets when they already provide the required behavior.
* Improve an existing reusable widget when practical.
* Add a reusable widget when no suitable widget exists.
* Avoid one-off editor-only layout and mouse-handling code.
* Layer editor-specific behavior on top of generic reusable widgets.
* Do not rewrite the entire editor during this phase.

## Current problem

The Phase 91 Events-tab implementation requires additional horizontal space.

Increasing the Property Inspector’s fixed width permanently reduces the Designer Canvas.

Add a draggable vertical splitter on the left edge of the Property Inspector so the user can resize the Designer Canvas and Property Inspector interactively.

## Reusable splitter requirements

Create or extend a genuine reusable VisiForm widget.

The splitter should support:

* vertical orientation
* horizontal orientation where practical
* two child panes
* draggable separator
* live resizing while dragging
* appropriate horizontal or vertical resize cursor
* visible separator
* a larger usable hit area than the visible divider
* minimum size constraints for both panes
* safe split-position clamping
* recalculation when the parent is resized
* mouse capture during dragging
* clean release after dragging
* safe handling when the pointer leaves the widget or application
* independent state for multiple splitter instances
* initial split position
* access to the current split position
* normal VisiForm styling conventions
* no dependencies on editor-specific classes

Possible names include:

* Splitter
* SplitterWidget
* SplitView

Choose the name that best matches existing VisiForm conventions.

## Editor integration

Use the reusable splitter between:

* first or left pane: Designer Canvas
* second or right pane: Property Inspector

Required behavior:

* The separator appears on the left edge of the Property Inspector.
* Dragging left widens the Property Inspector.
* Dragging right widens the Designer Canvas.
* The application window size remains unchanged.
* Both panes resize interactively.
* The Property Inspector has a sensible minimum width.
* The Designer Canvas has a sensible minimum width.
* Neither pane can collapse or receive invalid dimensions.
* Main-window resizing preserves a valid layout.
* The separator remains usable at minimum and maximum positions.
* Properties and Events tabs continue to work.
* Phase 91 event rows use additional inspector width correctly.
* Handler fields and Create, Existing, and Clear controls remain readable.
* Existing Widget Palette and Project Tree behavior does not regress.
* Existing left-side layout and separators continue working.

## Split-position state

Preserve the Property Inspector width or splitter position during the current application session.

Inspect the existing settings or preferences architecture.

If a suitable mechanism already exists:

* save the splitter position
* restore it on startup
* validate and clamp restored values
* use a safe default when no valid value exists

If no suitable mechanism exists:

* retain the value during the current session
* document cross-session persistence as deferred work
* do not introduce an unrelated settings subsystem without approval
