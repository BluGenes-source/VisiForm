2. Fix the initialization order
-------------------------------

Preferred solution:

- ensure every font used by `TextEditControl` has a valid DPI scale before any draw, hit-test, caret-position, or string-measurement call

- reapply DPI when canvas settings change

Do not rely solely on delaying the crash.

If a safe default is required before a canvas is available, use a deliberate default DPI scale of `1.0f`, then replace it with the real canvas DPI when known.

Avoid scattered one-off assignments. Use the existing font/canvas settings path where possible.

-----------------------------------------

Inspect `Font::dpiScale()` and its constructor behavior.

Only if consistent with the existing Visage design, make the runtime behavior defensive so a missing DPI does not cause a fatal assertion in normal application use.

Acceptable behavior:

- initialize `dpi_scale_` to `1.0f` in constructors, or
- return `1.0f` when the stored value is invalid while retaining an appropriate debug diagnostic

Do not silently conceal persistent incorrect DPI propagation.

The primary fix must still ensure the editor receives the actual DPI value.
