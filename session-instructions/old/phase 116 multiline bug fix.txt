## Goal 1: Use the Boolean editor

Ensure Multiline is described as a Boolean property and uses the existing Boolean editor.

Preferred UI:

- dropdown with `false` and `true`
- checkbox/toggle if that is the established inspector convention

Do not use a free-form text field for Boolean values.

Verify the property descriptor supplies:

- Boolean editor type
- valid values
- editable state
- correct property ID
- correct commit callback

## Goal 2: Trace the failed commit

Trace the current edit path:

1. user selects or enters `true`
2. editor commits its value
3. value is parsed as Boolean
4. Text Box model property is updated
5. command/undo system records the change
6. inspector refresh reads the updated value
7. canvas repaints

Determine where the value is being lost or rejected.

Possible causes:

- generic string editor is used
- Boolean parsing accepts only `1/0`
- commit callback still targets an Appearance override
- property name or ID does not match the model field
- model setter is missing
- refresh reads a different property source
- the command stores the old value again
- conditional visibility rebuild overwrites the edit

Record the confirmed root cause in the Phase 116 plan.

## Goal 3: Correct Boolean parsing and commit

Required behavior:

- selecting `true` stores Boolean true
- selecting `false` stores Boolean false
- closed row reflects the committed value
- canvas updates immediately
- the Text Box enters multiline behavior when true
- undo and redo work
- no-op changes create no undo entry
- save/reload preserves the value

Do not store the strings `"true"` or `"false"` if the model already uses a Boolean.

## Goal 4: Verify Word Wrap

Check Word Wrap through the same Boolean editor path.

Requirements:

- it can be changed between false and true
- it commits to the correct model property
- it becomes enabled or visible appropriately when Multiline is true
- it does not inherit stale editor metadata

Use the shared Boolean property editor fix rather than a Multiline-only workaround.
