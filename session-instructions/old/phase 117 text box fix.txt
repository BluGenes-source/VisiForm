## Preferred implementation

When a Text Box is activated in Preview Mode, create or show one reusable `TextEditControl` overlay positioned over that Text Box.

Do not create one editor instance for every Text Box.

The overlay must:

* use the selected Text Box’s exact view-space bounds
* account for canvas zoom and pan
* account for border and content padding
* receive real framework keyboard and text-input focus
* initialize from temporary Preview text
* use the resolved widget typography and appearance
* support single-line or multiline mode
* support Word Wrap
* remain editor-only and temporary

Use the existing working text editor rather than duplicating text-input logic in `DesignerCanvas`.

## Temporary data policy

The overlay edits only Preview state.

Required flow:

1. Enter Preview Mode.
2. Initialize temporary Text Box state from the model.
3. Click a Text Box.
4. Bind the reusable overlay editor to that widget’s temporary text.
5. Edit normally.
6. When focus changes, copy the overlay value back to temporary Preview state only.
7. When returning to that Text Box during the same Preview session, restore its temporary text.
8. On leaving Preview Mode, destroy or hide the overlay and discard all temporary values.

Never commit Preview text to `WidgetNode`.

Preview editing must not:

* mark the project dirty
* create project undo entries
* trigger autosave
* alter serialized data

## Overlay ownership and lifetime

Use one clearly owned Preview Text Box editor.

Show it only while a Preview Text Box is active.

Hide or detach it when:

* another Preview widget receives focus
* the active Text Box is deleted
* the project is replaced
* Preview Mode exits
* the canvas or form becomes invalid

Do not retain raw widget pointers across hierarchy rebuilds. Use stable IDs and resolve them safely.

## Focus

When the Preview Text Box is clicked:

* activate the overlay
* request real keyboard focus through the same API used by Design Mode editing
* place the caret at the clicked character boundary
* prevent the click from falling through to canvas commands

Do not display a caret unless the overlay actually owns keyboard focus.

## Geometry synchronization

Update overlay bounds when:

* canvas zoom changes
* canvas pan changes
* the application window resizes
* Project Tree or Property Inspector splitters move
* the Text Box geometry changes
* its parent/container layout changes

Hide the overlay if its widget becomes fully clipped or hidden.

Use the existing model-to-view transform exactly once.

## Editing behavior

Reuse `TextEditControl` support for:

* printable text
* caret blinking
* mouse caret placement
* selection
* Backspace and Delete
* arrows, Home, and End
* Ctrl+A, copy, cut, and paste
* Enter when Multiline is true
* multiline navigation
* Word Wrap
* scrolling

Configure it from the Text Box properties rather than implementing these again.

For read-only Text Boxes:

* permit selection and copying
* prevent text mutation

For disabled Text Boxes:

* do not activate the overlay

## Rendering

While the overlay is active:

* avoid drawing duplicate text underneath it
* keep the Text Box border and runtime styling consistent
* ensure the overlay visually matches the underlying widget
* do not show Design Mode selection or resize decorations

When the overlay is inactive, render the temporary Preview text through the normal Preview renderer.

## Preview focus navigation

When Tab or Shift+Tab moves focus to another Text Box:

* commit the outgoing overlay value to temporary state
* rebind the overlay to the incoming Text Box
* transfer real keyboard focus
* preserve all changes only within the current Preview session

For non-text widgets, hide the overlay before routing focus to them.

## Do not use fake success criteria

Do not consider the bug fixed merely because:

* the Preview focus ID changes
* a caret is painted manually
* a key-down handler runs
* a repaint occurs

The required result is that typed printable characters visibly alter the temporary Text Box content.
