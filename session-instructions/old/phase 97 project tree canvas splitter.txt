## Goal

Add a draggable vertical splitter between the Project Tree panel and the Designer Canvas.

The splitter must allow the user to resize the Project Tree width without affecting the existing Property Inspector splitter behavior.

## Required behavior

- the splitter appears between the Project Tree and Designer Canvas
- dragging it resizes both adjacent panels
- the Project Tree has a practical minimum width
- the Designer Canvas has a practical minimum width
- neither panel may collapse to zero width
- resizing remains smooth and stable
- maximizing and restoring the window preserves a usable layout
- the existing splitter between the canvas and Property Inspector continues to work
- splitter handles must not overlap panel borders or content
- the cursor should indicate horizontal resizing when hovering over the splitter, if supported by the existing UI framework

## Layout requirements

Preserve this workspace order:

1. Project Tree
2. new Project Tree / Canvas splitter
3. Designer Canvas
4. existing Canvas / Property Inspector splitter
5. Property Inspector

The new splitter should:

- use the same visual language as the existing splitter
- have a compact hit area
- remain easy to grab
- not consume excessive width
- resize only the two neighboring regions

Prefer the existing splitter widget or layout abstraction already used by VisiForm.

Do not implement separate custom mouse-drag code if the existing splitter control can be reused.

## Initial sizing

Choose a practical startup width for the Project Tree based on the current layout.

Requirements:

- Project Tree labels remain readable
- Designer Canvas receives most of the workspace width
- Property Inspector sizing remains unchanged unless required for layout correctness
- narrow windows remain usable

If splitter positions are already persisted, integrate this splitter with that mechanism.

If no persistence exists, use a sensible default and do not add a large persistence system solely for this phase.
