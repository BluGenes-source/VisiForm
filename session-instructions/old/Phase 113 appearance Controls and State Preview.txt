# Goal 1: Restore numeric sliders

The Property Inspector previously used sliders for appearance metrics such as:

* Corner Radius
* Border Thickness

They are now displayed only as text/numeric fields.

Restore the slider-based editors.

## Required behavior

For supported rectangular widgets:

* Corner Radius uses a slider with range `1–25`
* Border Thickness uses a slider with range `1–25`
* the numeric value remains visible
* dragging updates the value immediately
* keyboard entry remains available if the existing slider editor supports it
* invalid typed values are clamped or rejected safely
* changing the value repaints the widget immediately
* one completed edit creates one undoable change
* no-op edits create no undo entry

If zero is already a valid meaning for either property, preserve that existing behavior and use the correct range rather than forcing `1`.

Confirm the previous range and semantics from existing code or history before changing them.

## Root-cause investigation

Determine why the slider editors disappeared.

Possible causes include:

* Phase 112 state-property editor using a generic numeric editor
* compatibility metadata no longer marking the properties as slider-backed
* state and normal property descriptors using different editor types
* range metadata being dropped while building the Appearance section

Fix the shared property metadata or editor-selection path.

Do not add special hard-coded UI rows only for Button.

## Widget compatibility

Restore the sliders for all compatible rectangle-based widgets that support these properties, including where applicable:

* Button
* Text Box
* Combo Box
* List Box
* Progress Bar
* Color Picker
* Frame
* Group Box
* Panel
* Tab Control
* other widgets confirmed to use Corner Radius or Border Thickness

Hide or disable the fields for widgets where they have no visual effect.

## Normal and state appearance

Corner Radius and Border Thickness remain normal appearance metrics.

Do not create state-specific geometry overrides.

When editing Hover, Pressed, Focused, Checked, Selected, or Disabled states:

* continue inheriting Corner Radius and Border Thickness from Normal
* do not display misleading editable state sliders for these metrics

# Goal 2: Add Appearance State Preview

Add a controlled preview for the currently selected Appearance State.

The user should be able to preview:

* Normal
* Hover
* Pressed
* Focused
* Checked or Selected
* Disabled

without changing the stored widget state or entering full Preview Mode.

## UI behavior

Near the existing Appearance State selector, add a compact control such as:

* `Preview State`
* `Show State`
* or an equivalent existing UI pattern

Preferred behavior:

* selecting an Appearance State chooses which override data is edited
* enabling Preview State temporarily renders the selected widget using that state
* disabling Preview State returns it to normal Design Mode rendering
* changing the selected state updates the temporary preview immediately

Do not create a large new preview panel.

## Preview-state safety

The temporary state preview must:

* not change the project model
* not mark the project dirty
* not create undo history
* not change checked values, selected indexes, slider values, or enabled state
* not execute events
* not persist in `.vfb.json`
* clear when selection changes
* clear when the project changes
* clear when entering Preview Mode
* clear when the widget is deleted
* clear when the Appearance editor is closed or reset

Use one editor-only state override.

Do not duplicate the runtime state machine.

## Supported-state compatibility

Only offer valid states for the selected widget.

Examples:

* Button: Normal, Hover, Pressed, Focused, Disabled
* Check Box: Normal, Hover, Pressed, Focused, Checked, Disabled
* Radio Button: Normal, Hover, Pressed, Focused, Checked, Disabled
* List Box: Normal, Hover, Focused, Selected, Disabled
* Tab Control: Normal, Hover, Pressed, Focused, Selected, Disabled
* Progress Bar: Normal and Disabled unless additional states already exist

Hide or disable unsupported states.

## Design and Preview Mode interaction

In Design Mode:

* the temporary state preview may alter only the selected widget’s runtime-style appearance
* selection outline, resize handles, and editor overlays remain visible

When entering full Preview Mode:

* clear the Property Inspector temporary state preview
* use actual Preview Mode interactions and state handling

When returning to Design Mode:

* show the normal widget appearance unless the user explicitly enables state preview again
