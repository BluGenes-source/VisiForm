## Goal

Add two related Design Mode improvements:

1. Show selected-widget geometry in a dedicated status-bar section.
2. Make the selected widget’s upper-right corner handle open a popup listing its assigned callbacks.

The upper-right handle must retain resize support.

## Part 1: Status-bar geometry

When exactly one visual widget is selected, show:

`X: 310  Y: 230  W: 260  H: 56`

Use current model-space values.

Update immediately during:

* dragging
* resizing
* Property Inspector geometry edits
* undo and redo
* alignment commands
* docking or layout changes

Hide or clear the section when:

* nothing is selected
* multiple widgets are selected
* a nonvisual item is selected
* Preview Mode is active

Requirements:

* use a dedicated status-bar segment where practical
* preserve the existing hint and selected-widget sections
* do not overwrite temporary hint messages
* do not mark the project dirty
* do not serialize status information

Do not create a floating geometry badge.

## Part 2: Callback corner affordance

Use the selected widget’s upper-right selection handle as a callback-menu affordance.

Interaction rules:

* a click opens the callback popup
* a drag beyond the existing drag threshold performs normal upper-right resizing
* clicking must not start a resize
* dragging must not open the popup
* other resize handles remain unchanged

Use the existing mouse drag threshold or centralize one if needed.

Do not remove upper-right resize functionality.

## Corner appearance

When the selected widget has one or more assigned callbacks:

* give the upper-right handle a subtle callback indicator
* keep it consistent with existing selection-handle styling
* make it visually distinguishable without becoming distracting

Possible treatments:

* small dot
* compact event glyph
* accent outline
* small corner marker

When no callbacks are assigned:

* either retain the normal resize-handle appearance and allow a click to show an empty-state popup
* or show a subdued callback affordance

Prefer behavior that helps discoverability.

Do not redesign all selection handles.

## Assigned callback discovery

Use existing widget event metadata and assignments.

The popup must list callbacks that currently have assigned handlers.

Examples:

* `onClick`
* `onChange`
* `onTextChanged`
* `onSelectionChanged`

Use the event names already defined by VisiForm.

Do not hardcode callback names by widget type if existing metadata can provide them.

Do not show unassigned callbacks in the main assigned list.

## Popup menu

Clicking the upper-right handle opens a popup near that corner.

Popup requirements:

* remain inside the visible Designer Canvas or application window
* appear above canvas content
* close when clicking outside
* close with Escape
* close when selection changes
* close when the project changes
* close when entering Preview Mode
* contain no stale widget pointers

Use stable widget IDs where retained state is needed.

### Assigned callbacks

Display each assigned callback with its handler name where practical.

Example:

`onClick → handleSubmit`

### Empty state

When the widget has no assigned callbacks, show:

`No callbacks assigned`

Optionally include:

`Open Events Inspector`

Do not add a full callback editor inside the popup.

## Callback action

For this phase, clicking an assigned callback should:

1. keep the widget selected
2. switch the Property Inspector to the Events tab
3. reveal or select that callback row
4. focus or highlight its assigned-handler field where existing APIs allow
5. close the popup

Do not:

* execute the callback
* run generated code
* launch an external editor
* create a new handler automatically
* modify the callback assignment

If focusing the exact field requires a broad Property Inspector redesign, switch to the Events tab and scroll/highlight the callback row only.

## Optional popup command

The popup may include:

`Open Events Inspector`

This command should:

* switch to the Events tab
* show the selected widget’s event list
* make no project changes

Keep the popup small.

## Mouse handling

Preserve correct behavior for the upper-right handle.

### Click

Treat the gesture as a click when:

* pointer is pressed and released on the handle
* movement remains below the drag threshold
* the selected widget remains valid

Then open the callback popup.

### Drag

Treat the gesture as resize when:

* movement exceeds the drag threshold

Then:

* begin normal upper-right resize
* close any open callback popup
* preserve snapping and constraints
* create the normal resize undo operation

Do not create an undo entry for clicking the callback menu.

## Selection behavior

Show the corner callback affordance only when:

* exactly one visual widget is selected
* Design Mode is active

Hide it for:

* multi-selection
* project or form root selection
* nonvisual nodes
* Preview Mode

Changing selection must close the popup.

## Preserve existing behavior

Do not regress:

* all eight-direction resize behavior
* resize corner arcs
* dragging
* snapping
* guides
* grid
* multi-selection
* zoom and pan
* Property Inspector Properties tab
* Events tab editing
* undo and redo
* save/load
* export

The callback popup is editor-only and must not appear in generated projects.

## Scope boundaries

Do not add:

* callback execution
* callback simulation
* automatic handler generation
* source-code navigation
* external IDE launching
* event debugging
* breakpoint support
* a new event-assignment system
* Preview Mode interaction changes

Record possible callback actions as future work.
