# Phase 62 resource binding dropdown and property hints plan

## Phase title
Phase 62 resource binding dropdown and property hints

## Current problem
The `Resource Manager` can add image resources, but the `Image` widget does not provide a clear, discoverable way to bind a managed image resource. The current `resourceId` field requires manual entry, the label is not clear, property rows do not expose hover hints in the status bar, and the image preview does not clearly communicate the selected managed resource.

## Goal
Improve image resource binding and property discoverability by adding a reusable resource dropdown editor for `Image.resourceId`, clearer property labels, property hover hints in the status bar, better designer preview feedback, and supporting validation/export/documentation updates without breaking save, load, export, or generated project behavior.

## Diagnostic notes
- `ProjectDocument` stores managed resources in `ProjectDocument.resources` as a top-level `std::vector<ProjectResource>`.
- `ProjectResource` currently contains `id`, `type`, `displayName`, `sourcePath`, and `exportRelativePath` in `src/model/ProjectResource.h`.
- Image resources are identified by `ProjectResourceType::Image`.
- Resource ids are generated by `IdGenerator::next(ProjectResourceType, ProjectDocument)` using the `image_` prefix, so ids are currently shaped like `image_1`, `image_2`, and so on.
- `displayName` exists and is currently derived from the selected file stem when a resource is added.
- `sourcePath` exists and stores the original asset file path.
- `exportRelativePath` exists and stores the generated-project asset path under `assets/`.
- The current resource type enum explicitly supports `Image`.
- The current `Image` widget definition exposes `resourceId`, `imagePath`, `scaleMode`, and `hint` in `WidgetRegistry`.
- The current `resourceId` property key is exactly `resourceId`.
- The current `imagePath` property key is exactly `imagePath`, with legacy `source` used as a fallback in preview and export code.
- The current `scaleMode` property key is exactly `scaleMode`, with choices `Stretch`, `Fit`, `Fill`, and `Center`.
- `PropertyInspector` labels are currently taken directly from `WidgetPropertyDefinition.label`, and the `Image` widget still uses raw internal labels like `resourceId`, `imagePath`, and `scaleMode`.
- `PropertyInspector` currently appends image resource dropdown choices as raw ids only, with an empty-string first choice, so there is no readable display text and the stored value and shown value are the same.
- The confusing clipped `resourceId` label comes from the fixed `PropertyInspector` label column width (`kLabelColumnWidth = 104`) plus a text draw width of only `kLabelColumnWidth - 24`, which truncates raw camelCase keys into awkward partial text.
- Implementation progress: `PropertyInspector` now carries readable choice labels and property hints, `Image.resourceId` uses a managed-resource dropdown with `<none>`, the designer image placeholder now shows readable managed names, and the `Resource Manager` shows resource ids alongside display names.
